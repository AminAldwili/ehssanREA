# وثيقة متطلبات البرمجيات (SRS) — تطبيق أيادي للتبرّعات
**الجهة:** جهة حكومية ليبية (الاسم يُحدَّد) · **الإصدار:** 0.1 (مسودة) · **المرجع التحليلي:** إحسان 4.0.1

> ⚠️ **تنبيه:** نطاق هذه المسودة قديم. أيادي صار **مكمّلاً لمنصة البر الوقفية** ويغطي: الحالات الفردية، الزكاة، الإغاثة والطوارئ، كفالة الأيتام والأسر (انظر القسم 1ب في `ayadi-CONTEXT-HANDOFF.md`). تُحدَّث هذه الوثيقة في الجلسة A.

---

## 1. المقدمة والنطاق
أيادي منصّة تبرّعات رقمية تتيح للأفراد التبرّع لمشاريع وحملات خيرية تشرف عليها
الجهة. تُحصّل جميع الأموال في حساب الجهة عبر بوّابة دفع ليبية، وتُصرف
لكل حملة وفق حساب مستفيد يحدّده المشرف عند الإنشاء.

**خارج النطاق (المرحلة الأولى):** الزكاة، الوقف، الأضاحي، التبرّع بالدم، التبرّع
الدوري، الإهداء — تُؤجَّل لمراحل لاحقة.

---

## 2. المعمارية العامة
ثلاث مكوّنات وخادم واحد:
```
تطبيق العميل (Flutter)  ─┐
                         ├─► خادم API (Laravel) ─► قاعدة بيانات (MySQL/PostgreSQL)
لوحة الأدمن (Laravel+Filament, ويب) ─┘       │
                                            ├─► بوّابة دفع ليبية (معاملات/مسارات/سداد)
                                            ├─► مزوّد SMS (OTP: ليبيانا/المدار)
                                            ├─► Firebase (إشعارات + تحليلات)
                                            └─► تخزين صور (S3 / Cloudinary)
```
- **تطبيق واحد للعميل** على الجوال (Android/iOS من كود Flutter واحد).
- **لوحة أدمن ويب** منفصلة (ليست تطبيق جوال).
- **API موحّد** يخدم الاثنين، مع فصل صلاحيات.

---

## 3. الأدوار (Actors)
| الدور | يفعل |
|---|---|
| زائر | يتصفّح المشاريع دون تسجيل |
| متبرّع (مستخدم) | يسجّل OTP، يتبرّع، يتابع سجلّه وإيصالاته |
| مشرف محتوى (Admin) | ينشئ/يعدّل المشاريع والحملات، يحدّد حساب المستفيد |
| مدير مالي | يتابع التحصيل والصرف والتقارير والتسويات |
| مدير نظام | المستخدمون، الأدوار، الإعدادات، السجلّات |

## 4. المتطلبات الوظيفية — تطبيق العميل
**FR-C1 الدخول والهوية**
- تسجيل/دخول برقم الجوال + OTP عبر SMS.
- إصدار access_token + refresh_token؛ حفظ آمن (secure_storage)؛ تجديد تلقائي.
- دخول كضيف لتصفّح المشاريع؛ يُطلب التسجيل عند التبرّع.
- تسجيل خروج، حذف حساب.

**FR-C2 التصفّح والاكتشاف**
- شاشة رئيسية: بانرات، مشاريع مميّزة، فئات، حملات قريبة من الاكتمال.
- قائمة المشاريع مع فلترة (فئة، منطقة، نسبة الإنجاز) وبحث نصّي.
- تفاصيل المشروع: وصف، صور، الهدف، المُجمّع، نسبة الإنجاز، عدد المتبرّعين.

**FR-C3 التبرّع**
- تحديد مبلغ (قيم مقترحة + مبلغ مخصّص) بعملة الدينار الليبي (LYD).
- سلّة تبرّعات (عدّة مشاريع دفعة واحدة) — اختياري بالمرحلة الأولى.
- متابعة للدفع عبر بوّابة الدفع (WebView / SDK المزوّد).
- تأكيد الحالة من الخادم (لا يُعتمد على التطبيق).

**FR-C4 الإيصالات والسجلّ**
- شاشة نجاح + إيصال PDF قابل للحفظ/المشاركة.
- سجلّ تبرّعاتي (مكتملة/معلّقة/فاشلة) مع تفاصيل كل عملية.

**FR-C5 الملف الشخصي والإعدادات**
- بيانات المستخدم، تعديل رقم الجوال (بـ OTP).
- تفضيلات الإشعارات، اللغة (عربي/إنجليزي)، السياسات، "عن التطبيق"، تواصل/اقتراحات.

**FR-C6 الإشعارات**
- Firebase Messaging + إشعارات محلية؛ ربط التوكِن بالخادم؛ إشعار عند نجاح التبرّع أو تحديث حملة تابعها.

---

## 5. المتطلبات الوظيفية — لوحة الأدمن (ويب)
**FR-A1 المشاريع والحملات**
- إنشاء/تعديل/أرشفة مشروع: عنوان، وصف، فئة، منطقة، صور، مبلغ الهدف، تواريخ.
- حالات: مسودة → منشور → مكتمل/موقوف.

**FR-A2 حساب المستفيد (أساسي)**
- عند إنشاء الحملة، يحدّد المشرف **رقم حساب المستفيد** (وجهة الصرف) + اسم البنك.
- كل حملة مرتبطة بحساب وجهة واحد؛ يُعرض في التقارير.
- التحصيل يتم مركزياً في حساب الجهة (حساب التاجر)، والصرف لكل حملة وفق حسابها.

**FR-A3 المدفوعات والتسويات**
- عرض كل المعاملات (حالة، مبلغ، مرجع البوّابة، المشروع، المتبرّع).
- تقارير تحصيل حسب المشروع/الفترة؛ تصدير CSV/PDF؛ متابعة المبالغ المستحقّة للصرف لكل حساب مستفيد.

**FR-A4 المستخدمون والصلاحيات**
- إدارة المستخدمين، الأدوار (RBAC)، سجلّ العمليات (audit log).

**FR-A5 المحتوى والإعدادات**
- البانرات، الفئات، الصفحات الثابتة (سياسة، شروط)، إعدادات العملة ومزوّد الدفع.

---

## 6. آلية الأموال (Money Flow) — مفصّلة
```
المتبرّع يدفع ──► بوّابة الدفع ──► حساب التاجر = الجهة (تحصيل مركزي)
                                        │
          كل تبرّع يُقيَّد على حملته ──────┘
الحملة تحمل: beneficiary_account (حدّده الأدمن) + beneficiary_bank
          │
المدير المالي يتابع: جُمِع لكل حملة ──► يُصرف لحساب المستفيد المحدّد
```
- **collection_account:** ثابت = حساب الجهة لدى مزوّد الدفع.
- **beneficiary_account:** متغيّر لكل حملة، يحدّده الأدمن عند الإنشاء.
- النظام يسجّل لكل عملية: المبلغ، المشروع، حساب المستفيد المقصود، مرجع البوّابة، الحالة.
- التسوية الفعلية بين الجهة وحسابات المستفيدين تُدار كتقرير + حالة صرف (مدفوع/معلّق).

## 7. المتطلبات غير الوظيفية (NFR)
- **الأمان:** HTTPS فقط؛ التوكِنات في secure_storage؛ لا تُخزَّن أرقام بطاقات (توكِن من المزوّد)؛ تحقّق الدفع من جهة الخادم؛ حماية ضد Root/تلاعب (freerasp)؛ Rate limiting على OTP والدفع؛ audit log لكل عملية مالية.
- **الأداء:** تحميل أولي < 3 ث؛ كاش للمشاريع (hive)؛ ترقيم صفحات (pagination).
- **الواجهات (جودة عالية بمستوى إحسان):** هوية لونية موحّدة، خطوط عربية راقية (IBM Plex Arabic)، أنيميشن Rive، انتقالات ناعمة، دعم RTL كامل، وضع فاتح/داكن، حالات تحميل/فراغ/خطأ مصمّمة.
- **التوطين:** عربي (أساسي) + إنجليزي.
- **الموثوقية:** معالجة انقطاع الدفع (idempotency) حتى لا يُحتسب تبرّع مرتين.
- **الامتثال:** سياسة خصوصية وشروط استخدام؛ موافقة صريحة؛ حذف حساب.

## 10. خطة الباك-اند (Laravel)
- **Laravel 11** + **Sanctum** (توكِنات) + **Filament** (لوحة الأدمن) + **Spatie Permission** (RBAC).
- بنية: Controllers رفيعة → Services (منطق) → Repositories/Models → Resources (تنسيق الرد).
- **الدفع:** واجهة `PaymentGateway` مجرّدة + تنفيذ `MoamalatGateway`/`MasaratGateway` (نركّبه لمّا توفّر وثائق المزوّد)، مع `FakeGateway` للتطوير الآن.
- **idempotency** على إنشاء التبرّع والـ callback؛ **queue** لتوليد الإيصالات والإشعارات.
- توليد PDF للإيصال (dompdf). رفع الصور لمخزن كائنات.

---

## 11. خطة التنفيذ (مراحل)
1. **الأساس:** هيكل Flutter (auto_route/dio/provider/DI) + هيكل Laravel + قاعدة البيانات + Auth OTP (بمحاكاة SMS).
2. **المشاريع:** API + شاشات القائمة والتفاصيل + لوحة أدمن لإدارة الحملات وحساب المستفيد.
3. **التبرّع والدفع:** تدفّق التبرّع + FakeGateway + إيصال PDF + سجلّ التبرّعات.
4. **الإشعارات والتوطين والواجهات الراقية** (Rive، RTL، فاتح/داكن).
5. **تركيب بوّابة الدفع الليبية الحقيقية** + التسويات والتقارير.
6. **التصلّب الأمني** (freerasp، rate limiting، audit) + اختبارات + إطلاق تجريبي.

# أيادي — الخطة الكاملة من الصفر إلى الإطلاق
**لمن هذا الملف:** لأمين، وللمساعد (Claude) اللي بيشتغل معه في الجلسات الجاية.
**كيف تُستخدم:** أمين يفتح جلسة كلاود جديدة، يرفق هذا الملف مع `ayadi-CONTEXT-HANDOFF.md`، ويكتب: "نفّذ الجلسة A من الخطة".

---

## 0. تعليمات ثابتة للمساعد (تنطبق على كل جلسة)
1. **أسلوب التعليم:** أمين مبتدئ في الباك-إند. اشرح كل خطوة بالعربي المبسّط قبل تنفيذها، وبعد كل مفهوم جديد اسأله سؤال تحقّق قصير. لا تنفّذ دفعة كبيرة بدون شرح.
2. **السياق يعيش داخل الريبو، مو في الشات:** كل ريبو فيه `CLAUDE.md` (يقرأه Claude Code تلقائياً) و`docs/PROGRESS.md`. في نهاية كل جلسة حدّث `PROGRESS.md` (وين وقفنا، وش التالي، وأي قرار جديد). كذا الجلسة الجاية تبدأ من الريبو مباشرة بدون نسخ ولصق.
3. **Git:** فرع لكل جلسة (`feature/<اسم>`)، commits صغيرة واضحة، وفي آخر الجلسة Pull Request إلى `main`. لا ترفع أسرار (`.env`) أبداً، فقط `.env.example`.
4. **نهاية كل جلسة:** قل لأمين بالضبط: (أ) وش أنجزنا، (ب) وش يتأكد منه بنفسه، (ج) الجلسة التالية: كلاود أو لوكال، وأي ريبو يختار فيها، وش يكتب كأول رسالة.
5. **إذا شي يحتاج قرار من أمين** (أسماء، مزوّدين، تصميم): اسأله، لا تفترض.

## 1. الصورة الكبيرة

| القطعة | الريبو | التقنية | وين نطوّرها |
|---|---|---|---|
| الخادم (API) + لوحة الأدمن | `ayadi-api` | Laravel 13 + Sanctum + Filament | ☁️ كلاود |
| تطبيق الجوال | `ayadi-app` | Flutter (Android أولاً) | 💻 لوكال (ويندوز) |

- **لوحة الأدمن داخل `ayadi-api`** (Filament)، ما نحتاج ريبو ثالث.
- **الريبوين يتواصلون عبر الـ API فقط.** العقد بينهم ملف `docs/api/openapi.yaml` داخل `ayadi-api`، وكل endpoint جديد يُوثَّق فيه قبل ما يستخدمه التطبيق.
- **ترتيب كل ميزة:** endpoint في الخادم ← واجهة في التطبيق ببيانات وهمية ← ربط الواجهة بالـ endpoint.

## 2. حقائق عن البيئة (مهمة عشان ما نضيّع وقت)
- **جلسة الكلاود ما تقدر تنشئ ريبوهات على GitHub.** أمين ينشئها بنفسه من github.com.
- **جلسة الكلاود ما تقدر ترفع (push) إلا إذا تطبيق Claude على GitHub مثبّت على الريبو.** الربط من: https://claude.ai/connect-github
- **الريبوهات تُختار عند بداية الجلسة.** الجلسة اللي تحتاج الريبوين، لازم يختارهم أمين الاثنين وقت فتحها.
- **جلسة الكلاود مؤقتة:** أي شي ما انرفع على GitHub يضيع.
- **رصيد الكلاود ($100) ينتهي 5 نوفمبر 2026.** نخلّي أكبر قدر من شغل الخادم قبله.
- **ربط جلسة كلاود بمجلد على جهاز ويندوز (Remote Control) غير مدعوم** (يدعم Mac/Linux فقط). فالشغل اللوكال على Flutter يكون عبر **تطبيق Claude Code لسطح المكتب على ويندوز** مباشرة.
- جهاز أمين جاهز فيه: Git، Node/npm، VS Code، PHP 8.5، Composer 2.10 (عبر Herd).

## المرحلة 0 — تجهيز يسويه أمين بيده (مرة وحدة، ~30 دقيقة)
1. **اربط GitHub بـ Claude:** https://claude.ai/connect-github ← ثبّت تطبيق Claude على حسابك (اختر "All repositories" أو الريبوهات الجديدة).
2. **أنشئ ريبوين** من https://github.com/new — كل واحد: Private + علّم "Add a README":
   - `ayadi-api`
   - `ayadi-app`
3. **ثبّت تطبيق Claude Code لسطح المكتب** على ويندوز (من https://claude.com/claude-code) وسجّل دخولك.
4. احتفظ بالملفات الأربعة عندك: `ayadi-MASTER-PLAN.md` (هذا)، `ayadi-CONTEXT-HANDOFF.md`، `ayadi-SRS.md`، `ayadi-blueprint.md`.

✅ **جاهز لما:** الريبوين ظاهرين في حسابك، وتطبيق Claude مثبّت عليهم.

## الجلسة A — التأسيس (☁️ كلاود · اختر الريبوين: `ayadi-api` + `ayadi-app`)
**أول رسالة يكتبها أمين:** يرفق الملفات الأربعة ويكتب "نفّذ الجلسة A من الخطة".

**في `ayadi-api`:**
1. إنشاء مشروع Laravel داخل الريبو، `php artisan install:api`، قاعدة SQLite للتطوير.
2. إعادة بناء ميزة الحملات من `CONTEXT-HANDOFF` (القسم 7) كنقطة بداية.
3. إعداد الاختبارات (Pest) + اختبار لـ `GET /api/v1/campaigns` (نستخدم البادئة `/api/v1` من الآن).
4. `.env.example` نظيف، و`.gitignore` يمنع `.env` وقاعدة البيانات.
5. `docs/`: نقل SRS + blueprint + هذه الخطة، وإنشاء `docs/api/openapi.yaml` مبدئي و`docs/PROGRESS.md`.
6. `CLAUDE.md` في الجذر: ملخّص المشروع، أسلوب التعليم، أوامر التشغيل والاختبار، قواعد الكود.
7. GitHub Actions: تشغيل الاختبارات تلقائياً على كل PR.
8. `README.md`: كيف يشغّله أمين على جهازه (عبر Herd) ويختبره.
9. اقتراح **سكربت إعداد بيئة الكلاود** (setup script) يضيفه أمين من إعدادات البيئة، عشان كل جلسة جاية تبدأ جاهزة (`composer install`، تجهيز `.env` وقاعدة البيانات).

**في `ayadi-app`:**
1. `CLAUDE.md` + `docs/PROGRESS.md` + نسخة من `ayadi-blueprint.md` (قسم تقنيات إحسان).
2. ما ننشئ مشروع Flutter هنا (Flutter مو مثبّت في الكلاود، والإنشاء الصحيح يكون على جهاز أمين في الجلسة L1).

**تعليم:** شرح بنية مشروع Laravel، الـ migrations، الاختبارات، Git branches و PR.
✅ **جاهز لما:** PR مدموج في الريبوين، والاختبارات خضراء في GitHub Actions، وأمين شغّل الخادم على جهازه مرة.

## الجلسات B إلى F — بناء الخادم (☁️ كلاود · اختر `ayadi-api` فقط)
كل جلسة: **شرح ← تنفيذ مع أمين ← اختبارات ← تحديث openapi.yaml و PROGRESS.md ← PR.**
**أول رسالة:** "اقرأ docs/PROGRESS.md ونفّذ الجلسة <الحرف> من الخطة".

| الجلسة | الهدف | يتعلّم فيها أمين |
|---|---|---|
| **B — الحملات كاملة** | CRUD للحملات (`POST/PUT/DELETE`)، Form Requests للتحقق، API Resources لتنسيق الرد، الفئات والمناطق | POST، التحقق من المدخلات، رموز 201/422 |
| **C — الهوية (OTP)** | `request-otp` / `verify-otp` / `refresh` / `logout`، Sanctum، مزوّد SMS وهمي (يكتب الكود في السجل)، تحديد عدد المحاولات (rate limit) | التوكِن عملياً، middleware، الحماية من التخمين |
| **D — التبرّع والدفع** | جدولي `donations` و `payments`، `DonationService`، واجهة `PaymentGateway` + `FakeGateway`، webhook لتأكيد الدفع، idempotency، تحديث `collected_amount` بأمان | Services، المعاملات (transactions) في قاعدة البيانات، لماذا التأكيد من الخادم |
| **E — الإيصالات والإشعارات** | إيصال PDF، سجلّ تبرّعاتي، تسجيل `device_tokens`، Queue للمهام البطيئة | الطوابير (queues)، توليد الملفات |
| **F — لوحة الأدمن** | Filament: إدارة الحملات مع **حساب المستفيد والبنك**، المعاملات، تقارير التحصيل لكل حملة وحساب، الأدوار (Spatie)، سجل العمليات (audit log) | صلاحيات RBAC، لوحات الإدارة |

✅ **جاهز لما (بعد F):** كل endpoints المرحلة الأولى في SRS تشتغل ومختبرة وموثّقة في openapi.yaml، ولوحة الأدمن تنشئ حملة بحساب مستفيد.

## الجلسة L1 — تجهيز Flutter (💻 لوكال · Claude Code سطح المكتب · مجلد `ayadi-app`)
**قبلها يسوي أمين:**
1. `git clone` للريبوين في مجلد واحد، مثلاً `C:\Users\<اسمك>\projects\`.
2. يفتح Claude Code لسطح المكتب على مجلد `ayadi-app` ويكتب: "اقرأ CLAUDE.md و docs/PROGRESS.md ونفّذ الجلسة L1 من الخطة".

**في الجلسة (المساعد يوجّه أمين خطوة بخطوة):**
1. تثبيت Flutter SDK + Android Studio + محاكي Android، والتأكد بـ `flutter doctor`.
2. `flutter create` داخل الريبو باسم الحزمة (يُسأل أمين عنه، مثلاً `ly.ayadi.app`).
3. البنية: auto_route، dio، riverpod أو provider، flutter_secure_storage، hive، فصل الطبقات (UI / State / Repository / API).
4. الهوية البصرية: ألوان، خطوط عربية (IBM Plex Sans Arabic)، RTL، وضع فاتح/داكن، عربي + إنجليزي.
5. ملف إعدادات لعنوان الخادم:
   - المحاكي يوصل لخادم شغّال على نفس الجهاز عبر `http://10.0.2.2:8000/api/v1` (والخادم يُشغَّل بـ `php artisan serve --host=0.0.0.0`).
6. `flutter analyze` و `flutter test` + GitHub Actions لهم.

✅ **جاهز لما:** التطبيق يفتح على المحاكي بشاشة ترحيب بالهوية البصرية، و PR مدموج.

## الجلسات L2 إلى L4 — بناء التطبيق (💻 لوكال · `ayadi-app`، مع `ayadi-api` شغّال على نفس الجهاز)
| الجلسة | الهدف |
|---|---|
| **L2 — الواجهات ببيانات وهمية** | Splash، Onboarding، تسجيل الدخول/OTP، الرئيسية، قائمة الحملات، تفاصيل الحملة، شاشة التبرّع، النجاح، سجلّ تبرّعاتي، الملف الشخصي. جودة بمستوى إحسان: انتقالات ناعمة، حالات تحميل/فراغ/خطأ مصمّمة، Rive للأنيميشن البسيط. |
| **L3 — الربط بالخادم** | استبدال البيانات الوهمية بنداءات الـ API حسب openapi.yaml، تخزين التوكِن بأمان، interceptor لتجديد التوكِن، معالجة الأخطاء. |
| **L4 — الدفع والإيصالات والإشعارات** | شاشة الدفع (WebView مع FakeGateway الآن)، عرض/مشاركة الإيصال PDF، Firebase Messaging (يُنشئ أمين مشروع Firebase بحسابه). |

✅ **جاهز لما:** رحلة كاملة على المحاكي: تسجيل ← اختيار حملة ← تبرّع ← إيصال ← يظهر في لوحة الأدمن.

## المرحلة النهائية — الإطلاق (جلسات مختلطة)
1. **بوّابة الدفع الليبية الحقيقية:** تنفيذ `MoamalatGateway` أو غيرها مكان `FakeGateway` (يحتاج وثائق المزوّد وحساب تاجر باسم الجهة).
2. **مزوّد SMS حقيقي** للـ OTP (ليبيانا/المدار أو مزوّد رسائل).
3. **الاستضافة:** سيرفر للخادم + قاعدة MySQL/PostgreSQL + نطاق (مثل `api.ayadi.ly`) + HTTPS + نسخ احتياطي.
4. **الحماية:** فحص Root (freerasp)، مراجعة أمنية، rate limits، سجلات.
5. **النشر:** Google Play (حساب مطوّر)، اختبار تجريبي مغلق، ثم الإطلاق. iOS لاحقاً (يحتاج Mac وحساب Apple).

